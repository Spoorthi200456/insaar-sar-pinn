## 1. Context

The model maps predicted head change Δh to InSAR displacement in
`src/models/network.py:190`:

```python
d_pred = -biot_alpha.unsqueeze(-1) * delta_h      # labelled cm
```

Four separate things are wrong with this line (`docs/review.md` finding 2):

| # | Problem | Consequence |
|---|---|---|
| a | **Sign.** A head rise gives *negative* displacement. Physically, a head rise lowers effective stress, the aquifer skeleton expands, and the ground **rises**. | A working structure (recharge → head rise → uplift) can only be fitted with Δh < 0. Since R ≥ 0 (softplus), this pushes R toward 0, so working structures look like failures. |
| b | **Magnitude / units.** Biot α is dimensionless (0.4–0.8), so α·Δh is in **metres**, and the result is used as **centimetres**. α = 0.6 means "0.6 m of uplift per metre of head", about 1000× too large for real aquifers. The missing factor is compressibility × thickness (§3). | The coupling cannot be physically right at any α. |
| c | **No line-of-sight (LOS) projection.** Sentinel-1 measures motion along the radar line of sight, not vertical motion. | Up to ±10% error at 29–46° incidence even if everything else were right (cos 29° = 0.87, cos 46° = 0.69). |
| d | **The synthetic data shares the error.** `src/training/train.py:61` (`-α·head·0.01`) and `frontend/lib/synthetic.ts:65` (same formula) use the same wrong sign, plus a ×0.01 factor the model does not have. | Tests on synthetic data cannot catch (a)–(c): the model is fitting data generated by the same mistake. |

There is also a documentation conflict: `src/data/schemas.py:107` says
`los_displacement_cm` is "positive = uplift" (a vertical convention), while
CLAUDE.md now records the provisional LOS convention "positive = motion
toward the satellite".

**Intended outcome:** a coupling with the correct sign, correct units
(m → cm made explicit), an LOS projection using the per-structure incidence
angle, a synthetic generator that uses the *same* function, and tests that
fail on the current code.

## 2. Symbols and units

| symbol | meaning | units |
|---|---|---|
| h | hydraulic head | m |
| Δh(t) | head change since the first acquisition | m |
| p | pore-water pressure | Pa = N/m² |
| σ | total vertical stress (weight of everything above) | Pa |
| σ′ | effective stress (stress carried by the grain skeleton) | Pa |
| ρ_w | density of water ≈ 1000 | kg/m³ |
| g | gravitational acceleration ≈ 9.81 | m/s² |
| α_c | compressibility of the aquifer skeleton (vertical) | 1/Pa = m²/N |
| b | thickness of the deforming aquifer system | m |
| S_sk | skeletal specific storage = ρ_w g α_c | 1/m |
| S_k | skeletal storage coefficient = S_sk · b | dimensionless |
| Δb | change in thickness of the aquifer system (= vertical ground motion u_z if nothing below deforms) | m |
| u_z | vertical ground displacement, positive = up | m |
| θ | radar incidence angle at the structure (from Sentinel-1 metadata) | degrees |
| d_LOS | line-of-sight displacement, positive = toward the satellite (provisional) | cm |

**Note on "α":** three different quantities share this letter. Biot α
(dimensionless, `biot_coefficient_alpha`), aquifer compressibility α_c
(1/Pa), and the heading angle sometimes written α_h. This plan uses α_c for
compressibility and does **not** use Biot α in the coupling.

## 3. Derivation

### Step 1 — Terzaghi's effective-stress principle
σ = σ′ + p.
Total stress is shared between the grain skeleton (σ′) and the pore water
(p). Units: Pa = Pa + Pa. ✓
*Source:* Terzaghi (1925); Freeze & Cherry (1979) §2.10 "Effective stress";
Galloway & Burbey (2011), *Hydrogeology Journal* 19, "Review: Regional land
subsidence accompanying groundwater extraction".

(Biot's generalisation is σ = σ′ + α p, with α = 1 − K_skeleton/K_grain. For
unconsolidated sediments α ≈ 1, which recovers Terzaghi. For hard rock α < 1;
in that case α is absorbed into the measured S_k below, not used as a separate
coefficient. *Source:* Wang, *Theory of Linear Poroelasticity* (2000), ch. 2.)

### Step 2 — Recharge does not change the total stress
The weight of rock and water above the aquifer is unchanged by a head change
on the time scale of interest, so Δσ = 0, which gives
Δσ′ = −Δp.
*Source:* Freeze & Cherry (1979) §2.10 (the same assumption used to derive S_s).

### Step 3 — Pressure change from head change
h = z + p/(ρ_w g). At a fixed point (Δz = 0), Δp = ρ_w g Δh.
Units: [kg/m³]·[m/s²]·[m] = kg/(m·s²) = Pa. ✓
Therefore **Δσ′ = −ρ_w g Δh**: a head rise *reduces* effective stress.
*Source:* Freeze & Cherry (1979) §2.2 (definition of hydraulic head) and §2.10.

### Step 4 — Skeleton strain from effective-stress change
For one-dimensional (vertical) elastic compression:
Δb / b = −α_c Δσ′.
Units: [1/Pa]·[Pa] = dimensionless strain. ✓
The minus sign means more effective stress gives compression (b shrinks).
*Source:* Freeze & Cherry (1979) §2.10 (definition of aquifer compressibility);
Jacob (1940); Riley (1969).

### Step 5 — Combine steps 3 and 4
Δb = −α_c b (−ρ_w g Δh) = (ρ_w g α_c) · b · Δh = S_sk · b · Δh
⇒ **Δb = S_k · Δh**.
Units: [1/m]·[m]·[m] = m. ✓
*Source:* Galloway & Burbey (2011); Hoffmann, Zebker, Galloway & Amelung
(2001), *Water Resources Research* 37 ("Seasonal subsidence and rebound in Las
Vegas Valley…"), where this exact relation, Δb = S_k Δh, is used to estimate
S_k from InSAR and well heads.

**Sign check:** Δh > 0 (recharge) gives Δb > 0, i.e. **uplift**. The current
code gives the opposite sign.

### Step 6 — Ground motion equals aquifer-system thickness change
If the layers below the aquifer system do not deform, u_z = Δb = S_k Δh [m].
*Source:* Galloway & Burbey (2011) (standard compaction-equals-subsidence
assumption).

### Step 7 — Project onto the radar line of sight
Let ê be the unit vector from the ground to the satellite. Then
d_LOS = **u** · ê. With horizontal motion neglected (assumption A3 below),
only the vertical part survives:
d_LOS = u_z · cos θ.
With the provisional convention "positive = toward satellite", uplift gives
d_LOS > 0. ✓
*Source:* Hanssen, *Radar Interferometry* (2001), ch. 2 (LOS geometry);
Wright, Parsons & Lu (2004), *GRL* 31 (decomposition of LOS into components).

### Step 8 — Convert m to cm (explicit unit conversion, not a fitted scale)
**d_LOS [cm] = 100 [cm/m] · cos θ · S_k · Δh [m].**
Every factor has known units. The 100 is the m → cm conversion, written as a
named constant (`CM_PER_M = 100.0`), not a tuning knob.

### Why Biot α alone cannot be the coefficient
α·Δh has units of metres and α ≈ 0.6, so it predicts 0.6 m of motion per metre
of head. The real coefficient is S_k = ρ_w g α_c b. Using indicative
compressibilities from Freeze & Cherry (1979) Table 2.5 (verify against your
edition):

| aquifer system | α_c (1/Pa) | b (m) | S_k = ρ_w g α_c b | u_z for Δh = 2 m |
|---|---|---|---|---|
| sound / weathered hard rock (granite, basalt) | ~1e-10 | ~20 | ~2e-5 | ~0.04 mm |
| sand / gravel | ~1e-8 | ~50 | ~5e-3 | ~1 cm |
| clay-rich alluvium (interbeds) | ~1e-7 (elastic) | ~100 | ~1e-1 (upper end) | ~20 cm (upper bound; real elastic values lower) |

These are **order-of-magnitude** values only; field estimates of elastic S_k
from InSAR studies are typically around 1e-5 to 1e-3 (Hoffmann et al. 2001;
Galloway & Burbey 2011).

## 4. Assumptions (all provisional, to be confirmed)

| id | assumption | when it breaks |
|---|---|---|
| A1 | **Elastic** deformation only (head stays above its historic minimum, the preconsolidation head). | In over-exploited Indian aquifers, heads below historic lows cause *inelastic* compaction with S_kv ≈ 10–100 × S_ke that does **not** rebound. A rising head after inelastic compaction gives much less uplift than this model predicts. |
| A2 | **No time lag.** Deformation follows head immediately. | Thick clay interbeds drain slowly, so their compaction lags head by months to years (Riley 1969). |
| A3 | **Vertical motion only**; horizontal motion neglected. | Near a recharge mound, horizontal motion can be a noticeable fraction of vertical. Fixing this needs ascending + descending tracks; the schema already has `track_direction`. |
| A4 | **One track per structure series** (no mixing of ascending and descending). | Mixing tracks makes one θ per structure meaningless. Enforce with a validator. |
| A5 | **InSAR displacement is relative** to the first acquisition and to a reference point. | If the processor's reference point moves, d has an unknown offset per structure. Currently the integrator gives Δh(t₀) ≠ 0 at step 0; see Q6. |
| A6 | **LOS sign = positive toward satellite.** | Processors differ; check the documentation of whichever tool produces the time series (e.g. MintPy documents positive = toward the satellite). If the data use the opposite sign, flip it **once**, at ingestion in the schema, never in the model. |

## 5. ⚠ Feasibility risk to the project goal (needs a supervisor discussion)

The derivation says detectability depends on geology, not on the model:

- **Hard-rock aquifers** (most check dams and percolation tanks in peninsular
  India): S_k ~ 1e-5, so 2 m of seasonal head change gives about **0.04 mm**
  of uplift. Sentinel-1 time-series precision is roughly a few mm per epoch,
  so **aquifer deformation from recharge is likely invisible** there.
- **Alluvial aquifers** (Indo-Gangetic plain, coastal deltas): S_k ~ 1e-4 to
  1e-3 gives about 0.2–2 mm per metre of head, which is measurable over a
  season.
- **Structure deformation itself** (bund settlement, cracking, seepage-driven
  subsidence at the dam) is a different signal at the structure footprint.
  InSAR may detect *failure* through this route even where aquifer recharge
  is invisible.

This does **not** change the fixed goal, but it may change where the method
can work, and which InSAR signal answers "working vs failing". The plan
below makes the model honest about it: with S_k small, it will predict near-zero
displacement instead of inventing recharge to explain noise.

## 6. Proposed code changes (Phase A — finding 2 only)

### 6.1 One shared coupling function — `src/models/coupling.py` (new)
```python
CM_PER_M = 100.0

def head_to_los_cm(delta_h_m, skeletal_storage, incidence_deg):
    """d_LOS [cm] = 100 · cos(θ) · S_k · Δh   (+ = toward satellite; uplift > 0)
    delta_h_m (B,T) [m]; skeletal_storage S_k scalar or (B,) [–]; incidence_deg (B,) [deg]."""
    cos_theta = torch.cos(torch.deg2rad(incidence_deg)).unsqueeze(-1)
    s_k = skeletal_storage.reshape(-1, 1) if skeletal_storage.dim() > 0 else skeletal_storage
    return CM_PER_M * cos_theta * s_k * delta_h_m
```
Used by the model, the Python synthetic generator, and (via a mirrored
TypeScript version) the frontend generator, so they cannot drift apart again.

## 7. Identifiability (say this to the faculty)

InSAR alone constrains only the product S_k·Δh. Head Δh is itself set by
R/S. So from displacement data alone the model can trade a larger S_k
against a smaller recharge. **Without head observations, "working vs
failing" cannot be separated from "stiff vs compliant aquifer".** The schema
already has `well_series` (well head observations), but the loss never uses
it. Adding a well-head data term is the single most important next step after
this finding. It is a new loss term, so it gets its own plan (Phase B).
